# Molay AI v3 — مشروع أولي للأندرويد + خادم بحث وبرمجة

هذه نسخة مطوّرة من النموذج الأولي، وفيها:
- تطبيق Android بواجهة عربية داكنة.
- واجهة خادم FastAPI منفصلة للمحادثة والبحث وتوليد الشيفرات.
- محرك بحث تجميعي: يرسل الاستعلام إلى SearXNG قابل للضبط، مع DuckDuckGo HTML كخيار احتياطي، ويضيف نتائج Wikipedia عند الملاءمة.
- إجابات أحدث بالمعلومات المتاحة: وضع البحث يضيف نتائج الويب وروابطها إلى سياق النموذج. لا يضمن تغطية كل الإنترنت أو صحة كل نتيجة.
- توليد شيفرات برمجية عبر Ollama، مع إمكانية إرفاق نتائج البحث الحديثة إلى الطلب.
- مسار Tor اختياري على الخادم عبر SOCKS5؛ يحتاج إلى Tor daemon/proxy يعمل فعلًا على الخادم. لا يجعل التطبيق نفسه متصلًا بـTor تلقائيًا.
- لا يتضمن تشغيل الشيفرات التي يولدها النموذج تلقائيًا. راجعها واختبرها داخل بيئة معزولة قبل استخدامها.

## مهم
هذا **مصدر مشروع** وليس APK جاهزًا. بناء APK باستخدام Buildozer يحتاج عادةً Linux أو macOS، أو Linux عبر WSL. راجع:
https://buildozer.readthedocs.io/en/1.6.0/quickstart/

## تشغيل الخادم (Linux / Windows / macOS)
1. ثبّت Python 3.11 أو أحدث.
2. من مجلد `backend`:
   `python -m venv .venv`
3. فعّل البيئة الافتراضية ثم:
   `pip install -r requirements.txt`
4. انسخ `.env.example` إلى `.env` وعدّل الإعدادات.
5. شغّل:
   `uvicorn server:app --host 0.0.0.0 --port 8000`

إعدادات `.env`:
- `OLLAMA_URL`: عنوان واجهة Ollama، افتراضيًا `http://127.0.0.1:11434`
- `OLLAMA_MODEL`: اسم النموذج المثبت في Ollama.
- `SEARXNG_URL`: عنوان نسخة SearXNG تثق بها (اختياري).
- `TOR_SOCKS_PROXY`: مثل `socks5h://127.0.0.1:9050` إذا شغّلت Tor على الخادم.
- `API_KEY`: ضع كلمة سر طويلة؛ التطبيق يرسلها في ترويسة `X-API-Key`.
- `ALLOW_DDG_FALLBACK`: يتيح محاولة DuckDuckGo HTML عند غياب SearXNG.

## تشغيل التطبيق على هاتف حقيقي
1. شغّل الخادم على كمبيوتر/خادم متصل بالشبكة.
2. اجعل الهاتف والخادم على الشبكة نفسها، أو استخدم اتصالًا آمنًا مستضافًا.
3. افتح إعدادات Molay AI واكتب عنوان الخادم، مثل `http://192.168.1.20:8000`، ثم API Key نفسه.
4. لا تعرض الخادم على الإنترنت مباشرة دون HTTPS وجدار حماية ومفتاح قوي.

## Tor والخصوصية
- مسار Tor يعمل على **الخادم** فقط إذا كان Tor proxy مضبوطًا ومتاحًا.
- استخدمه للبحث القانوني والآمن فقط. لا يوجد ضمان بأن كل مواقع `.onion` ستعمل أو أن نتائجها موثوقة.
- لا ترسل كلمات مرور أو معلومات شخصية حساسة إلى مصادر مجهولة.
- لا تستخدم الخدمة لبناء برمجيات خبيثة أو سرقة بيانات أو تجاوز أنظمة حماية.
- لا تستخدم وضع Tor كدليل على إخفاء الهوية الكامل؛ إعدادات الشبكة والسجلات قد تكشف معلومات.

## بناء APK
من مجلد `android` في Linux/WSL بعد تثبيت Buildozer:
`buildozer -v android debug`
ينتج ملف APK عادةً داخل `bin/`.
قد تحتاج إلى تعديل متطلبات Buildozer بحسب إصدار Android وبيئة البناء.

## ما الذي لا تعد به هذه النسخة؟
- لا تملك معرفة مطلقة أو تحديثًا لكل معلومة لحظة بلحظة؛ تعتمد على نتائج البحث المتاحة واتصال الخادم والنموذج.
- لا تتصفح كل الويب أو كل شبكة Tor تلقائيًا؛ البحث التجميعي يجلب نتائج محدودة لكل استعلام.
- لا تُعد نظامًا مستقلًا يبرمج ويشغّل أي برنامج بلا مراجعة. التوليد متاح، لكن التنفيذ التلقائي معطّل عمدًا.


## بناء APK من الهاتف فقط عبر GitHub Actions
أضفت ملف سير عمل إلى `.github/workflows/build-apk.yml` لتجربة البناء على خادم GitHub:
1. أنشئ مستودعًا جديدًا في GitHub من المتصفح.
2. ارفع محتويات هذا المشروع إلى المستودع مع المجلد المخفي `.github`.
3. افتح تبويب Actions، واختر `Build Molay AI Android APK`، ثم `Run workflow`.
4. عند انتهاء البناء، افتح التشغيل الناجح ونزّل Artifact باسم `Molay-AI-Android-APK`.
5. فك ضغط الـArtifact على الهاتف ثم ثبّت APK. قد يطلب Android السماح بالتثبيت من مصدر المتصفح/مدير الملفات.

ملاحظة: هذا سير عمل مقترح ولم يُختبر في بيئة GitHub فعلية من داخل هذه المحادثة. إذا فشل البناء، افتح سجل Actions وانسخ رسالة الخطأ لمعالجتها. لا تضع مفاتيح API أو أسرارًا في المستودع العام.
